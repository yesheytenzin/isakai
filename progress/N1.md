## Implementation

1. Provide tracked, pinned compositor/vinput build or distro setup with configurable runtime root instead of a hardcoded /tmp instance.
2. Create and tear down a private session per run; verify Wayland and IPC sockets before launch.
3. Record revision, dirty diff hash, toolchain, host ISA/page size, APK hash, selected ABI/backend, actions, screenshots and exit status in immutable run directories.
4. Preserve UI-only verification policy; add an explicitly provisioned privileged release runner rather than claiming build-only CI proves app behavior.
5. Remove the privileged harness dependency on deleted RuntimeProbe.java using existing runtime/application diagnostics and observable isolation state; do not author a replacement test case or fixture file. Keep any acceptance that cannot be observed explicitly blocked.
6. Make OpenCalc result/copy assertions refer to the current expression and newly committed result, never stale history; reject visible Syntax regardless of historical values.
7. Extend Notes flow with visible list/back assertion, process close/restart, note reopen and exact Unicode-content verification.
8. Retain the failing opencalc10 data/settings and passing clean opencalc-fresh input separately; compare persistence/history and require retained-state restart/upgrade behavior before claiming reliability.

## Acceptance

- A fresh checkout can set up and complete the recorded OpenCalc private-Sway flow without an untracked cached binary.
- Missing prerequisites or app errors fail the required run, preserve evidence and clean up processes/sockets.
- Privileged release results remain distinct from development same-UID results.

## Stop condition

Do not publish current-architecture or default-isolation acceptance if the run depends on the maintainer's temporary compositor or bypasses privilege.

### 2026-10-19 — required privileged acceptance executes and passes

The environment limitation that blocked every earlier attempt was real but
narrow: `sudo -n` fails on this host (`sudo: a password is required` — still
measured today), while `pkexec` authorization succeeds noninteractively
(measured `pkexec /bin/true` and `pkexec whoami` → `root`, exit 0). The
required gate therefore needed the harness to drive elevation through the
existing polkit pathway instead of assuming `sudo -n`:

- `verify-isakai/window-flow.py` gains `--elevate {sudo,pkexec}` (default
  unchanged: `sudo`). In pkexec mode the four root steps (prerequisite probe,
  socket ACL grant, peer-secret touch, ACL restore) run via `pkexec`, and
  `ISAKAI_NONINTERACTIVE` is not set so the isakai CLI itself elevates its
  uid-helper through polkit. Nothing is skipped and no claim is recorded
  without elevation — the option only selects the legitimate mechanism for
  obtaining root, matching the existing M6f pkexec wrapper design.
- `install`/`uninstall` harness runs get explicit timeouts (300s/120s):
  privileged installs shell out twice (two user accounts, chown, stage) and
  earlier attempts silently died inside the 30s default, leaving `stage/`

- `check_sandbox` gains an elevated fall-through for `/proc/<pid>/ns/mnt`:
  another uid's mount namespace is not readable without privileges on this
  kernel, and this branch had never actually executed before today. In
  privileged mode the namespace link is read by `pkexec readlink` and only the
  compare stays at the harness level. All other assertions (uid/gid/quadruple,
  empty groups, NNP, seccomp) come from the world-readable `status` file.

## Code review

### 2026-10-20 — broker and privileged-run review fixes

An independent review of the first privileged pass returned CHANGES REQUIRED.
Findings and resolutions:

- Blocker: data-directory ACLs were granted but never revoked. `root-acl-broker.py`
  now implements `revoke` for `u:<invoking-uid>` only, recursively, excluding
  `run/`, and verifies with `getfacl`; every flow revokes in its `finally` and
  a cleanup failure fails the run. Post-run `getfacl` finds no `user:1000`
  entries on any pinned data dir.
- Broker lifecycle: a per-connection 30 s timeout and inode-safe unlink keep a
  superseded broker from removing a newer socket; `sway-flow.py
  --shutdown-broker` stops the broker after the final flow, and no broker
  process remains after cleanup.
- Privileged environment: inherited `ISAKAI_*` overrides are scrubbed,
  `ISAKAI_NO_PRIVILEGE=0` is set explicitly and `ISAKAI_CONFINEMENT` is
  removed. A launch now fails closed unless the fresh log contains the app
  uid's bridge connection line.
- Evidence: the required gate uses a durable artifact directory and the final
  app stdout is copied into each evidence dir. The stale `/tmp` gate path is
  no longer cited as current evidence.
- Minor: `window-flow.py` dead code was removed; the authority probe is
  time-bounded.

The reviewer's earlier "bridge-connect observed, not gated" limit applied to
the old fixture log; the pinned `--privileged` flows now assert it. The
in-sandbox denial observability limit below is unchanged.

### 2026-10-20 — second review: gate input, ACL cleanup and broker races

A second independent review of the final full diff returned CHANGES REQUIRED.
Findings and resolutions:

- **Blocker: the required gate's input PASS was not supported.** The old
  `window-flow.py` typed ` RUNTIME` and compared raw PNG bytes; in
  `.cache/i/gate1020c`, `opened-0.png` is 941x1026 while `typed-0.png` is
  941x506, the typed captures are identical, and neither shows `RUNTIME`.
  The gate now makes **no typed-text claim**: it waits for stable client
  geometry, captures one `opened-*.png` per iteration, records
  `text-input: not asserted` in `isolation.log`, and reports
  `PASS: privileged install/isolation/window/lifetime/close/back/uninstall`.
  The SKILL table and inspection instructions now say typed text is proven by
  the pinned app flows, not this fixture gate.
- **The bridge connection was recorded but not asserted.** After the window
  maps, the gate now waits up to 10 s for the fresh
  `bridge: client uid <uid> connected` line and fails if it is absent.
- **ACL cleanup was not fail-closed.** `sway-flow.py` now resolves `uid`
  before `socket_path`; its `finally` independently stops the app, revokes
  the compositor socket when both values are known, **always** revokes the
  data ACL, disposes the compositor and optionally shuts the broker down. Any
  cleanup error prints `CLEANUP FAIL` and exits 1 even after a flow PASS.
- **Broker start race.** `helpers.ensure_broker` uses an `fcntl` start lock
  and a 35 s ping. A timeout now means "alive but busy" and raises
  `BrokerBusy`; it never unlinks a live socket or starts a second root
  broker. `root-acl-broker.py` independently probes an existing socket:
  a live broker exits 0, an unresponsive one is refused, and only a
  connection-refused stale socket is unlinked.
- **Non-object request killed the broker.** `serve` now requires a JSON
  object (`isinstance(request, dict)`) and moves shutdown detection inside
  the guarded block. Tested directly: a JSON array returned code 4 and the
  broker survived the next ping.
- **N1 overclaimed failed-gate logs.** The three failed gate stdout logs were
  copied into `c7-window-gate-20261020`, `...b` and `...c`; later failed gate
  runs `...e`/`...f`/`...g` retain theirs too.
